# 開発環境

AviUtl2 のスクリプトはビルド不要です。所定のフォルダに置けば、AviUtl2 に読み込まれます。

## フォルダ構成

| パス | 内容 |
| --- | --- |
| `script/` | 公開するスクリプト本体。AviUtl2 の Script フォルダにリンクする |
| `samples/` | 動作確認用のダミー連番画像（リポジトリに同梱。[サンプル画像](#サンプル画像) を参照） |
| `tools/` | 開発用の補助スクリプト |
| `docs/` | 開発者向けの資料 |
| `local/` | 個人用の作業フォルダ（Git 管理外。実素材やプロジェクトファイルはここへ） |

## 初回セットアップ

1. VS Code でこのフォルダを開き、推奨拡張機能（Lua、EditorConfig）を入れる。
2. 開発用リンクを作成する。

   ```powershell
   pwsh tools/link-dev.ps1
   ```

   `C:\ProgramData\aviutl2\Script\renban-matome-dev` が、このリポジトリの `script/` を指すようになります。
   解除するときは `pwsh tools/unlink-dev.ps1` を実行します（リポジトリのファイルは消えません）。

## サンプル画像

`samples/` の画像は、`tools/` のスクリプトで描いた画像です。
リポジトリに同梱しているので、普段はスクリプトを実行する必要はありません。

| フォルダ | 内容 | 生成スクリプト |
| --- | --- | --- |
| `samples/number/` | 数字 0～10（11 枚） | `tools/make-dummy-images.ps1` |
| `samples/bar/` | 0～10 割合のバー（11 枚） | `tools/make-dummy-images.ps1` |
| `samples/animation/` | 猫の AA が魚のばねの玩具を猫パンチする。30fps・5 秒（150 枚）、ループ可 | `tools/make-animation-images.py` |

絵を変えたいときだけ、スクリプトを編集して次のように作り直します。

```powershell
pwsh tools/make-dummy-images.ps1
```

```powershell
uv run --with pyoxipng python tools/make-animation-images.py
```

- `make-animation-images.py` は zopfli 圧縮のため、数分かかります。  
- 生成結果は Pillow・フォント（MS Pゴシック）・oxipng のバージョンで変わることがあります。作り直すと全ファイルが差し替わり履歴に残るので、絵を変えるとき以外は実行しないでください。  
- 自動テストは `bar`・`number` を入力に使います。これらを作り直したら、テストが通ることを確かめてください。  

## 動作確認の流れ

1. AviUtl2 を起動する。
2. 「オブジェクト追加」→「開発確認」→「_開発確認」を置く。
   画面に本体のバージョン番号などが表示されれば、セットアップは完了です。
3. `script/` のファイルを編集して保存する。
4. AviUtl2 に反映する。
   - **処理内容（Lua のコード）の変更**: 「キャッシュを破棄」で再読み込みされます。
   - **設定項目（`--track` などの先頭の定義）の変更**: AviUtl2 の再起動が必要です。
     また、新しいスクリプトファイルを追加したときも再起動が必要です。

## デバッグ

- `print("...")` の出力は、AviUtl2 のログに出ます。
- ログのファイルは `C:\ProgramData\aviutl2\Log\` にもあります。

## 本体のバージョン番号（`--require` に書く値）

`obj.getinfo("version")` が返す番号は、ウィンドウに表示されるバージョンと形式が違います。

| 画面の表示 | バージョン番号 | 確認方法 |
| --- | --- | --- |
| 2.1.17 | `2011700` | 「_開発確認」で実測（2026-11-07） |
| 2.00 beta35 | `2003500` | lua.txt の `--require` の例 |

「2.1.17 → 2 / 01 / 17 / 00」のように、2桁ずつ並べた形と読めます。

## 「スクリプトの種類」と追加のしかた

| 拡張子 | 種類 | 追加のしかた |
| --- | --- | --- |
| `.obj2` | カスタムオブジェクト | タイムラインの「オブジェクト追加」から、単独のオブジェクトとして置く |
| `.anm2` | アニメーション効果（フィルタ効果） | オブジェクト設定ウィンドウの [+] から、既存のオブジェクトに付ける。1つのオブジェクトに複数付けられる |

「_開発確認」は `.obj2` なので、[+] の一覧には出ません。
「連番まとめ」は、次の2つで構成します（要件定義書 1.6.1）。

| ファイル | 種類 | 役割 |
| --- | --- | --- |
| `script/連番まとめ（値）.obj2` | カスタムオブジェクト（土台） | 値を4つ持ち、公開し、連番スロットの画像をまとめて描く |
| `script/連番スロット.anm2` | フィルタ効果 | 1つの連番画像の設定（画像・従う値・オフセット・上限・X・Y・拡大率）を持つだけ。処理は何もしない |

土台は、自分に付いたフィルタ効果の名前を `obj.getoption("script_name", 位置, true)` で上から調べ、
「従う値」の項目を持つものを連番スロットとみなして、`obj.getvalue("効果名:n", "項目名")` で設定を読みます。
効果名を固定で書かないので、利用者がファイル名を変えても動きます。
用途別の連番スロット（たとえば回転や透明度を持つもの）を足すときも、「従う値」の項目を持たせれば、土台はそのまま読めます（要件 RM-F20）。

土台は、連番スロット1つを1つの個別オブジェクトとして描きます。位置と大きさ（`obj.ox`・`obj.oy`・`obj.zoom`）は、`obj.load()` の**後に**設定します。読み込むと元に戻るためです。
個別オブジェクトの番号は、利用者との取り決めにしていません（要件 RM-F18 は取り下げ）。

## 確認済みの注意点

実機で確認した AviUtl2 の動きは、[要件定義書 2.11](../requirements.md#211-実機で確認した事実) にまとめています。
特に実装に効くものは次のとおりです。

- **何も描かないオブジェクトには、フィルタ効果が実行されない。** 土台は、案内を出さないときは何も描かない（付いた連番スロットは実行されなくてよい）。
- **カスタムオブジェクトの中では `obj.getoption("script_name")` が空になる。** 案内の見出しは固定の文字列にしている。
- **`obj.getvalue()` は、対象が無いとき値を返さない。** `tostring(obj.getvalue(...))` のように直接渡すとエラーになるので、いったん変数に入れる。
- **動画の出力中は `obj.getoption("gui")` が false。** 自動テストの描画も出力扱いなので、「案内の表示：編集中だけ」でプレビューに出ることは、AviUtl2 上で目で確かめる。
- **中間点が効かないとき**：トラックバーの移動方法が「直線移動(時間制御)」「補間移動(時間制御)」だと、中間点の時間が無視されます。利用者向けの説明書にも載せる。

## 自動テスト

[aviutl2-pyrrhulina](https://github.com/osakanamaki/aviutl2-pyrrhulina) で、AviUtl2 を実際に起動して描画結果を確かめる。
Releases の wheel を `pyproject.toml` で参照している。

```sh
uv sync
uv run task test
```

- `.aup2` に書くリスト選択（`--select`）の値は、番号ではなく選択肢の名前。
- **証跡のパスが 260 文字を超えると、AviUtl2 が結果を書かずに異常終了する。** 証跡のフォルダ名はテスト名から作られ、日本語は `_u30b9` のように長くなる。テスト名と parametrize の id は、短い英数字にする（worktree のように深いフォルダで実行すると、特に起きやすい）。
- 案内の見た目は、`assert_snapshot` で基準画像（`tests/baselines/`）と比べている。案内の文言や見た目を変えたら、テスト後に表示される `index.html` で目で確かめてから、基準画像を書き直す。

  ```sh
  uv run pytest -k guide --aviutl2-update-baselines
  ```

  フォント（Yu Gothic UI）や AviUtl2 本体の更新でも一致しなくなることがある。

## ファイルの書き方の決まり

- 文字コードは UTF-8（BOM なし）、改行は CRLF。`.editorconfig` と `.gitattributes` で設定済みです。
- 仕様の一次資料は、AviUtl2 本体に同梱されている `C:\Program Files\AviUtl2\lua.txt` です。
  Web のドキュメント（docs.aviutl2.jp）は有志のミラーで、本文と更新履歴に差があることがあります。
