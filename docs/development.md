# 開発環境

AviUtl2 のスクリプトはビルド不要です。所定のフォルダに置けば、AviUtl2 に読み込まれます。

## フォルダ構成

| パス | 内容 |
| --- | --- |
| `script/` | 公開するスクリプト本体。AviUtl2 の Script フォルダにリンクする |
| `samples/` | 動作確認用のダミー連番画像（リポジトリに同梱。[サンプル画像](#サンプル画像) を参照） |
| `tools/` | 開発用の補助スクリプト |
| `docs/` | 開発者向けの資料 |
| `local/` | 個人用の作業フォルダ（Git 管理外。実素材やプロジェクトファイルはここへ） |

## 初回セットアップ

1. VS Code でこのフォルダを開き、推奨拡張機能（Lua、EditorConfig）を入れる。
2. 開発用リンクを作成する。

   ```powershell
   pwsh tools/link-dev.ps1
   ```

   `C:\ProgramData\aviutl2\Script\renban-matome-dev` が、このリポジトリの `script/` を指すようになります。
   解除するときは `pwsh tools/unlink-dev.ps1` を実行します（リポジトリのファイルは消えません）。

## サンプル画像

`samples/` の画像は、`tools/` のスクリプトで描いた画像です。
リポジトリに同梱しているので、普段はスクリプトを実行する必要はありません。

| フォルダ | 内容 | 生成スクリプト |
| --- | --- | --- |
| `samples/number/` | 数字 0～10（11 枚） | `tools/make-dummy-images.ps1` |
| `samples/bar/` | 0～10 割合のバー（11 枚） | `tools/make-dummy-images.ps1` |
| `samples/animation/` | 猫の AA が魚のばねの玩具を猫パンチする。30fps・5 秒（150 枚）、ループ可 | `tools/make-animation-images.py` |

絵を変えたいときだけ、スクリプトを編集して次のように作り直します。

```powershell
pwsh tools/make-dummy-images.ps1
```

```powershell
uv run --with pyoxipng python tools/make-animation-images.py
```

- `make-animation-images.py` は zopfli 圧縮のため、数分かかります。  
- 生成結果は Pillow・フォント（MS Pゴシック）・oxipng のバージョンで変わることがあります。作り直すと全ファイルが差し替わり履歴に残るので、絵を変えるとき以外は実行しないでください。  
- 自動テストは `bar`・`number` を入力に使います。これらを作り直したら、テストが通ることを確かめてください。  

## 動作確認の流れ

1. AviUtl2 を起動する。
2. 「オブジェクト追加」→「連番まとめ」→「連番まとめ（値）」を置き、選択する。
   「[連番まとめ]」の案内が表示されれば、セットアップは完了です。
3. `script/` のファイルを編集して保存する。
4. AviUtl2 に反映する。
   - **処理内容（Lua のコード）の変更**: 「キャッシュを破棄」で再読み込みされます。
   - **設定項目（`--track` などの先頭の定義）の変更**: AviUtl2 の再起動が必要です。
     また、新しいスクリプトファイルを追加したときも再起動が必要です。

## デバッグ

- `print("...")` の出力は、AviUtl2 のログに出ます。
- ログのファイルは `C:\ProgramData\aviutl2\Log\` にもあります。

## 本体のバージョン番号（`--require` に書く値）

`obj.getinfo("version")` が返す番号は、ウィンドウに表示されるバージョンと形式が違います。

| 画面の表示 | バージョン番号 | 確認方法 |
| --- | --- | --- |
| 2.1.17 | `2011700` | 開発用のスクリプトで `obj.getinfo("version")` を表示して実測（2026-11-07） |
| 2.00 beta35 | `2003500` | lua.txt の `--require` の例 |

「2.1.17 → 2 / 01 / 17 / 00」のように、2桁ずつ並べた形と読めます。

## 「スクリプトの種類」と追加のしかた

| 拡張子 | 種類 | 追加のしかた |
| --- | --- | --- |
| `.obj2` | カスタムオブジェクト | タイムラインの「オブジェクト追加」から、単独のオブジェクトとして置く |
| `.anm2` | アニメーション効果（フィルタ効果） | オブジェクト設定ウィンドウの [+] から、既存のオブジェクトに付ける。1つのオブジェクトに複数付けられる |

「連番まとめ」は、土台1つと、土台に付けるスロットで構成します（要件定義書 1.6.1）。

| ファイル | 種類 | スロットの種類 | 役割 |
| --- | --- | --- | --- |
| `script/連番まとめ（値）.obj2` | カスタムオブジェクト（土台） | | 値を8つ持ち、付いたスロットをまとめて描く |
| `script/連番スロット.anm2` | フィルタ効果 | `連番` | 画像・従う値・範囲外の扱い・枚数・X・Y・拡大率 |
| `script/計算式スロット.anm2` | フィルタ効果 | `計算式` | 連番スロットの「従う値」を「計算式」にしたもの |
| `script/数値スロット.anm2` | フィルタ効果 | `数値` | テキスト（`{式}` を計算して埋める）と、「テキスト」と同じ文字の項目 |
| `script/並べスロット.anm2` | フィルタ効果 | `並べ` | 画像・画像を選ぶ値・数を決める値・折り返しの数・余白・並べ方 |

スロットは設定の入れ物で、処理は何もしません。描画と計算は、すべて土台が行います。

### 土台がスロットを見分けるしくみ

各スロットは、隠した項目「スロットの種類」を持ちます（要件 RM-F23）。

```lua
--value@slot_kind:スロットの種類,"連番"
--hide@slot_kind
```

`--hide` で利用者には見えませんが、`obj.getvalue()` では文字列として読めます（要件定義書 2.11）。
土台は、自分に付いたフィルタ効果の名前を `obj.getoption("script_name", 位置, true)` で上から調べ、
「スロットの種類」を `obj.getvalue("効果名:n", "スロットの種類")` で読んで、種類ごとに設定を読みます。

- 効果名を固定で書かないので、利用者がファイル名を変えても動きます。
- 「スロットの種類」を持たないフィルタ効果は、スロットではないとみなして飛ばします。
- 土台が知らない種類のときは、「この土台は「X」のスロットに対応していません。」と案内します。
- 用途別のスロット（たとえば回転や透明度を持つ連番スロット）を足すときは、既存の種類の項目を持たせ、同じ種類名にすれば、土台はそのまま読めます（要件 RM-F20）。

### 描き方

土台は、描くもの1つを1つの個別オブジェクトとして描きます（並べスロットは、並べる数だけ）。位置と大きさ（`obj.ox`・`obj.oy`・`obj.zoom`）は、`obj.load()` の**後に**設定します。読み込むと元に戻るためです。
個別オブジェクトの番号は、利用者との取り決めにしていません（要件 RM-F18 は取り下げ）。

### 設定項目の数の上限

設定項目は、スクリプトの先頭に `local 変数名=値;` として差し込まれます。LuaJIT のローカル変数は 200 個までなので、
**設定項目と本文の最上位の `local` を合わせて 196 個以下**にしてください（要件定義書 2.11）。
`--group` は数に入りません。土台の値の数（8つ）は、この余裕を残して決めています。

## 計算式の評価（計算式スロット・数値スロット）

計算式は利用者が書く文字列で、それを Lua のコードとして実行します。
プロジェクトファイルを配った相手の PC でも実行されるので、**数の計算しかできない**ように、土台の `evaluate_formula()` で次の3段階の守りを掛けています。

1. **字句の検査**（`find_formula_problem()`）。実行する前に、式の文字列を調べます。
   - 記号 `" ' [ ] { } ;` があれば実行しません。文字列・表・長い文字列・複数の文を作れなくするためです。
   - 名前（英字・`_`・日本語で始まる並び）を前から順に調べ、次のものだけを通します。
     - `値1`〜`値8`
     - 予約語 `and` `or` `not` `true` `false`（`function` や `while` などは書けない）
     - `math` と、`math.` の後ろの許可した名前（`FORMULA_MATH_NAMES`）
   - 数字の直後の名前（`1e5` の `e5`、`0x1F` の `x1F`）は、数の一部なので通します。
   - `math.` 以外の `.` の後ろの名前と、`:` によるメソッド呼び出しの名前は通しません。
2. **見える名前を絞った実行**。`loadstring("return (" .. 式 .. ")")` で1つの式として読み込み、
   `setfenv()` で、`値1`〜`値8` と `math` の許可した関数だけを持つ表を、式の環境にします。
   字句の検査をすり抜けても、`io`・`os`・`require`・`loadstring` などは見えません。
3. **結果の検査**。`pcall()` で実行し、エラー・数でない結果・NaN・無限大は使いません。

許可している数学の名前は `abs` `ceil` `floor` `fmod` `max` `min` `sqrt` `pi` `huge` です。
`math.random` は、描くたびに結果が変わり、同じフレームの見た目が定まらないので除いています。
名前を足すときは、副作用が無く、同じ入力で同じ結果を返すものに限ってください。

`値1` のような日本語の名前は、LuaJIT がそのまま識別子として受け付けます（要件定義書 2.11）。
`{value_1}` のような置き換え方式にしなかったのは、置き換えた後の名前が式の中の別の名前とぶつかるおそれがあるためです。

計算できないときは、何も描かず、次の案内を出します。

| 案内 | 起きるとき |
| --- | --- |
| 計算式が空です。 | 計算式が空 |
| 計算式を計算できません：式（理由） | 字句の検査で止めた。理由は「使えない記号」「使えない名前」「使えない関数」 |
| 計算式を読めません：式 | 文法の誤り（`loadstring` が失敗） |
| 計算式の結果が数になりません：式 | 実行時のエラー、または結果が数・有限でない |

試験は `tests/test_renban_matome.py` の `test_formula_rejected` にあります。
守りを変えたときは、`io`・`os`・`require`・`loadstring`・`function`・文字列・メソッド呼び出しなどを使う式が、実行されずに案内になることを確かめてください。

## 確認済みの注意点

実機で確認した AviUtl2 の動きは、[要件定義書 2.11](../requirements.md#211-実機で確認した事実) にまとめています。
特に実装に効くものは次のとおりです。

- **何も描かないオブジェクトには、フィルタ効果が実行されない。** 土台は、案内を出さないときは何も描かない（付いた連番スロットは実行されなくてよい）。
- **カスタムオブジェクトの中では `obj.getoption("script_name")` が空になる。** 案内の見出しは固定の文字列にしている。
- **`obj.getvalue()` は、対象が無いとき値を返さない。** `tostring(obj.getvalue(...))` のように直接渡すとエラーになるので、いったん変数に入れる。
- **`obj.getoption("gui")` は、オブジェクト設定ウィンドウで選んでいるオブジェクトをプレビューで描くときだけ true。** 動画の出力中は false。「案内の表示：選択中だけ」はこれで判定している。
- **中間点が効かないとき**：トラックバーの移動方法が「直線移動(時間制御)」「補間移動(時間制御)」だと、中間点の時間が無視されます。利用者向けの説明書にも載せる。

## 自動テスト

[aviutl2-pyrrhulina](https://github.com/osakanamaki/aviutl2-pyrrhulina) で、AviUtl2 を実際に起動して描画結果を確かめる。
Releases の wheel を `pyproject.toml` で参照している。

```sh
uv sync
uv run task test
```

- `.aup2` に書くリスト選択（`--select`）の値は、番号ではなく選択肢の名前。
- **証跡のパスが 260 文字を超えると、AviUtl2 が結果を書かずに異常終了する。** 証跡のフォルダ名はテスト名から作られ、日本語は `_u30b9` のように長くなる。テスト名と parametrize の id は、短い英数字にする（worktree のように深いフォルダで実行すると、特に起きやすい）。
- 「選択中だけ」の確かめには、aviutl2-pyrrhulina v0.2.1 の `aviutl2.render(project, frames, selected=オブジェクト)` を使う。選んだオブジェクトでは `obj.getoption("gui")` が true になる。
- `tests/scripts/` には、テスト専用のスクリプト（土台が知らない種類のスロット `_試験_未知のスロット.anm2`）を置いている。
- 土台の値の範囲は -1〜999 なので、-2 以下の番号は計算式スロットで作って確かめる。
- `.aup2` の項目の値に改行を含めると、ファイルが壊れる。テストのテキストは1行にする。
- 案内の見た目は、`assert_snapshot` で基準画像（`tests/baselines/`）と比べている。案内の文言や見た目を変えたら、テスト後に表示される `index.html` で目で確かめてから、基準画像を書き直す。

  ```sh
  uv run pytest -k guide --aviutl2-update-baselines
  ```

  フォント（Yu Gothic UI）や AviUtl2 本体の更新でも一致しなくなることがある。

## ファイルの書き方の決まり

- 文字コードは UTF-8（BOM なし）、改行は CRLF。`.editorconfig` と `.gitattributes` で設定済みです。
- 仕様の一次資料は、AviUtl2 本体に同梱されている `C:\Program Files\AviUtl2\lua.txt` です。
  Web のドキュメント（docs.aviutl2.jp）は有志のミラーで、本文と更新履歴に差があることがあります。
